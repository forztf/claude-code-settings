请按照以下步骤分析和修复 GitHub 问题 $ARGUMENTS：

# 计划

1. 使用 'gh issue view' 获取问题详情
2. 了解问题中描述的问题
3. 如有必要，请提出澄清问题
4. 了解此问题的先前工作
   - 搜索草稿本中与问题相关的先前想法
   - 搜索 PR 以查看您是否可以找到此问题的历史
   - 搜索代码库中的相关文件
5. 更深入地思考如何将问题分解为一系列小的、可管理的任务。
6. 在新的草稿本中记录您的计划
   - 在文件名中包含问题名称
   - 在草稿本中包含问题的链接。

# 创建

- 为问题创建新分支
- 根据您的计划，以小的、可管理的步骤解决问题。
- 在每个步骤后提交您的更改。

# 测试

- 如果您对 UI 进行了更改并且 puppeteer 在您的工具列表中，请通过 MCP 使用 puppeteer 测试更改。
- 编写单元测试以描述代码的预期行为。
- 运行完整的测试套件以确保您没有破坏任何内容
- 如果测试失败，请修复它们
- 在继续下一步之前确保所有测试都通过

# 打开拉取请求

- 打开 PR 并请求审查。

请记住，对于所有与 GitHub 相关的任务，请使用 GitHub CLI ('gh')。
