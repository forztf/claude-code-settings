# Kiro 工作流图

## 主工作流状态机

此图显示了从初始创建到任务执行的完整工作流：

```mermaid
stateDiagram-v2
  [*] --> 需求 : 初始创建

  需求 : 编写需求
  设计 : 编写设计
  任务 : 编写任务

  需求 --> 审查需求 : 完成需求
  审查需求 --> 需求 : 请求反馈/更改
  审查需求 --> 设计 : 明确批准

  设计 --> 审查设计 : 完成设计
  审查设计 --> 设计 : 请求反馈/更改
  审查设计 --> 任务 : 明确批准

  任务 --> 审查任务 : 完成任务
  审查任务 --> 任务 : 请求反馈/更改
  审查任务 --> [*] : 明确批准

  执行 : 执行任务

  state "入口点" as EP {
      [*] --> 需求 : 更新
      [*] --> 设计 : 更新
      [*] --> 任务 : 更新
      [*] --> 执行 : 执行任务
  }

  执行 --> [*] : 完成
```

## 阶段进度

此简化图显示了通过阶段的线性进度：

```mermaid
graph LR
    A[想法] --> B[需求]
    B --> C{已批准?}
    C -->|否| B
    C -->|是| D[设计]
    D --> E{已批准?}
    E -->|否| D
    E -->|是| F[任务]
    F --> G{已批准?}
    G -->|否| F
    G -->|是| H[执行]
    H --> I[完成]
```

## 工作流入口点

用户可以在不同点进入工作流：

```mermaid
graph TD
    A[用户请求] --> B{什么阶段?}
    B -->|新功能| C[开始需求]
    B -->|更新需求| D[编辑需求]
    B -->|创建设计| E[开始设计]
    B -->|更新设计| F[编辑设计]
    B -->|生成任务| G[创建任务]
    B -->|更新任务| H[编辑任务]
    B -->|执行任务| I[运行任务]

    C --> J[需求文档]
    D --> J
    E --> K[设计文档]
    F --> K
    G --> L[任务文档]
    H --> L
    I --> M[实施]
```

## 批准关卡

每个阶段都有一个明确的批准关卡：

```mermaid
sequenceDiagram
    participant U as 用户
    participant K as Kiro
    participant D as 文档

    K->>D: 创建/更新文档
    K->>U: "这看起来可以吗？"
    U->>K: 反馈
    K->>D: 根据反馈更新
    K->>U: "这看起来可以吗？"
    U->>K: "是的，批准了"
    K->>K: 进入下一阶段
```

## 任务执行流程

```mermaid
graph TD
    A[用户：执行任务 X] --> B[读取规格文件]
    B --> C[requirements.md]
    B --> D[design.md]
    B --> E[tasks.md]

    C --> F[了解上下文]
    D --> F
    E --> F

    F --> G[识别任务]
    G --> H{有子任务?}
    H -->|是| I[先执行子任务]
    H -->|否| J[实施任务]

    I --> K[完成子任务]
    K --> L{更多子任务?}
    L -->|是| I
    L -->|否| J

    J --> M[停止 - 等待审查]
    M --> N[用户批准]
    N --> O{更多任务?}
    O -->|是| A
    O -->|否| P[功能完成]
```
